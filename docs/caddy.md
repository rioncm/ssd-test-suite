# Serve results with Caddy

Caddy only reads static files. It does not run the test suite, receive disk commands, or need root/block-device access. Run the test runner separately in a terminal.

After installing Caddy using its supported Ubuntu installation method, merge the example into your existing Caddy configuration rather than overwriting unrelated sites:

```caddyfile
http://localhost:8080 {
    bind 127.0.0.1
    root * /srv/ssd-results
    encode gzip
    file_server
}
```

This binds the site to localhost. For a trusted LAN, change the address to `:8080`, remove `bind 127.0.0.1`, and restrict access with your network/firewall policy. For a domain with HTTPS, use the appropriate hostname and your normal Caddy authentication/access controls. Public exposure is not required for this suite.

Validate the resulting configuration before reloading:

```bash
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
```

Visit `http://localhost:8080/` on the serving machine, or the LAN address if configured. The index is generated by the first run. The example intentionally does not enable directory browsing; each report links to its evidence files.

The runner creates new result directories/files with readable permissions (directories 0755, files normally 0644). Caddy needs traversal permission on parent directories. It should have **read access only**, not ownership or write access. Do not serve the source directory or an entire home directory. A 403 often means missing traversal/read permissions; a 404 before the first run means no index exists yet.

The Caddy configuration is an example, not installed automatically. See [Caddy static file server documentation](https://caddyserver.com/docs/caddyfile/directives/file_server) and [official installation instructions](https://caddyserver.com/docs/install).
